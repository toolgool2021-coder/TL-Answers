# TL Answers | Full Release 1.0

Закрытая учебная платформа одного класса. Клиент: статический HTML, Firebase Authentication и Realtime Database. Хостинг: GitHub Pages. Участники получают доступ только после ручного одобрения OWNER.

## Функции

- Лента владельца: заголовок, текст, предмет, категория, до 4 изображений (сжатие в браузере), закрепление, редактирование, удаление, поиск, фильтр по предмету.
- Избранное и архив отдельно для каждого пользователя.
- Чат онлайн: ответы, реакции, индикатор подключения, история, ограничение 5–10 секунд на запись по серверному времени; мут на час и блокировка.
- Вопросы: история пользователя, ответы лично или публично, удаление. Приватные ответы в `questions/{uid}` доступны только владельцу и автору.
- Firebase Auth: email+пароль, ручное одобрение, отклонение/блокировка, восстановление пароля, профиль, аватар.
- Панель OWNER: публикации, заявки, вопросы, настройки, модерация, журнал действий.
- Тёмная/светлая тема, мобильная нижняя панель, десктопная боковая панель, skeleton loading, адаптивная верстка.
- Push-уведомлений и центра уведомлений нет.

## ВАЖНО: активировать правила базы данных

**GitHub не публикует правила Firebase автоматически.** До включения новых возможностей администратору необходимо:

1. Открыть [Firebase Console](https://console.firebase.google.com/project/tl-answers/database/tl-answers-default-rtdb/rules).
2. Перейти в **Realtime Database → Rules** (не Cloud Firestore).
3. Скопировать весь текст [database.rules.json](./database.rules.json), заменить текущие правила и нажать **Publish**.
4. Открыть **Authentication → Sign-in method** и включить **Email/Password**.
5. В **Authentication → Settings → Authorized domains** проверить домены `answers.toolgool.site` и `toolgool2021-coder.github.io`. Если домен отсутствует, добавить его.
6. Создать пробный пользовательский аккаунт и подтвердить его в панели OWNER. UID владельца не меняется: `dLMJYKdfMoZUMYOablhE8uMn2HB2`.

**Важно:** при смене формата данных старые записи `chat/{uid}/{slot}` читаются как история. Новые сообщения записываются в `chat/{slot}/{uid}`. Legacy-публикации с полем `photo` поддерживаются в интерфейсе. Новые публикации используют `images`. Не удаляйте базу при обновлении.

### Необходимые проверки безопасности

Рекомендуется в Firebase Emulator Suite проверить для анонимного, ожидающего, одобренного, заблокированного пользователя и владельца:
- отсутствие чтения `posts/chat/questions` до одобрения;
- невозможность изменить собственное поле `status`;
- запрет другим участникам читать `questions/{anotherUid}`;
- запрет всем кроме OWNER на создание и изменение публикаций, выдачу публичных ответов и модерацию;
- запрет записи сообщений при выключенном чате, техперерыве и активном муте;
- запрет слишком частых сообщений и неправильного `uid`.

## Публикация

1. GitHub → Settings → Pages → **Deploy from a branch** → `main` → `/(root)`.
2. В DNS домена создать запись **CNAME**: `answers` → `toolgool2021-coder.github.io`.
3. В GitHub Pages проверить custom domain `answers.toolgool.site` и включить HTTPS, когда DNS разрешится. Файл [CNAME](./CNAME) уже подготовлен.
4. После развёртывания посетить `https://answers.toolgool.site`.

## Проверка исходников

Запустить локально `node tests/smoke.mjs`. Проверяет формат JSON правил, наличие критичных ограничений и синтаксис JavaScript модуля. Workflow GitHub Actions запускает ту же проверку при push и pull request.

Это **статические** проверки. Полноценные интеграционные и нагрузочные тесты Firebase и браузера должны выполняться отдельно. Настоящая защищённость зависит от того, что обновлённые правила действительно опубликованы в Firebase Console.

## Ограничения

Изображения сохраняются как сжатые data URI в Realtime Database (без Storage), поэтому ограничены размером; для больших файлов потребуется Firebase Storage с отдельными правилами. Лента загружает не более 150 последних публикаций, чат 150 последних временных групп. Серверная защита от спама использует ближайший предыдущий временной слот и не является многоуровневым антифлудом; для расширенного анализа злоупотреблений понадобятся Cloud Functions/App Check. Журнал фиксирует действия в клиенте OWNER, но не действия из Firebase Console.
